                      How these controls work
                      Autopilot
                      Autopilot is the master switch for the assistant's queue. On each pass the assistant looks for ready tasks, starts them while a worker slot is free, and verifies what came back. Turning it off stops new work from starting; jobs already running finish normally.
                      Parallel builds
                      How many builds may run at the same time. Machine managed starts work while the app stays responsive and backs off when the machine is busy. A manual limit (1–3) caps concurrent builds but never starts or pauses anything by itself.
                      Build mode
                      Auto build starts eligible tasks as soon as a worker is free. Verify first holds every new or changed brief for your approval, so you decide what gets built. Switching never interrupts a running job.
                      Agent mode
                      How agents coordinate. Swarm works across all ready tasks and their subtasks; Cluster focuses every agent on one shared task until it is done. Both plan, delegate and review results; current work finishes when you switch. The selector sits in the node tree toolbar under Agents.
                      New work
                      The master switch for starting anything new — queued tasks, builds and work the assistant suggests — lives with the Assistant. Off pauses admission; running jobs, replies and your answers to questions still work.

                      Done log

                      Loading…

                      Finished builds from the durable executor ledger, plus the assistant's own completed passes. Done means the worker reported success; Failed means it stopped early. These records survive restarts until you absorb them.
